## What is fixed

**Meeting detection (1.14.0).** `meeting-transcription-stop` cleared
`_userRecording` but not `_meetingModeActive`, and every detection is dropped
while that latch is set. The only thing that cleared it was a button that isn't
rendered in a wide window. Also: both native children are now supervised and
restarted, the macOS polling fallback reports `unavailable` instead of pretending
to work (the ioreg key it greps does not exist on modern hardware), latches age
out, and waking from sleep revalidates. A passive health registry feeds a
Settings status row.

**Local model context (1.15.0).** `llama-server` was started with no
`--ctx-size`; its default is "use the context the model was trained for" —
131,072 tokens for the bundled Gemma, **13.1 GB of KV cache** reserved before any
work, next to 5 GB of weights on a 24 GB machine. That is what made the whole
machine unresponsive. Context is now derived from the model's GGUF geometry and
available memory: **131072 → 32768, 13.1 GB → 3.28 GB** (verified against the
real file).

**Logging (1.15.0).** New `notice` level (35) that always persists, 30-day
retention with a 60-file backstop, and instrumentation on server start (model,
resolved context, estimated KV) and every inference (prompt size, output size,
elapsed; `warn` past 60 s).

## What is NOT done — the actual next job

**Long transcripts still fail instead of being processed in passes.** With the
context bounded and multi-pass unbuilt, an over-long note action now fails fast
with a translated message. The user asked for the opposite of cutting calls
short, chose **extract → compose**, and does not have it yet.

**Job queue.** Clicking generate on several old meetings at once fails. See
"Queue findings" below — most of the infrastructure already exists.

These two are **the same piece of work**: extract→compose is N sequential model
jobs that must not starve dictation, which is exactly the priority queue. Build
them together or the queue gets built twice. The user was asked to confirm this
and had not answered as of this handoff.

### Queue findings (already investigated)

- `src/helpers/backgroundJobQueue.js` **already exists** — serial, one job at a
  time, emits `status` (`running`/`complete`/`error`).
- `get-pipeline-status` IPC **already exists** and is bridged at `preload.js:337`
  as `getPipelineStatus`, returning `{queueLength, activeJob}`. **No renderer
  consumer.** The indicator the user wants is mostly plumbed already.
- Two different "generate" paths, only one queued:
  - `regenerateNotes` (`NoteEditor.tsx:684`) → main → `backgroundJobQueue` →
    pipeline. Queues correctly, but returns `{success:true}` instantly with no
    per-note UI state, so it looks like nothing happened.
  - note actions (`PersonalNotesView` → `runBackgroundAction`) → renderer →
    `reasoningService` → local bridge → **throws** when busy. Not queued at all.
- `PersonalNotesView.tsx:1035-1063` parses transcript segments and **discards
  them**, passing only a pre-joined string — so any chunker needs a signature
  change to receive segments. `parseTranscriptSegments` lives in
  `src/utils/parseTranscriptSegments.ts`.

## Design already settled (do not re-litigate)

From the user, 2026-08-11:

1. **Extract → compose**, not map-reduce (double compression loses the specifics
   they care about) and not rolling notes (one bad pass poisons the rest).
2. **Run with progress, no consent prompt.** Show "pass k of N", stay
   cancellable. Do not gate the run behind a confirmation dialog.
3. **No automatic cloud routing.** A user running local inference on meeting
   audio has made a privacy decision.

From the adversarial review of the first plan, already folded into
`docs/plans/2026-08-11-local-llm-context-and-long-transcripts.md`:

- **Local-only chunking** (C2: no cloud model declares a context).
- **No extract cache in v1** (C3: the proposed key was unsound in both
  directions — chunk boundaries move with the budget, and editing one character
  of manual notes busted the whole cache).
- **Mutex-busy is transient**, never a gap marker (I1). Abort after K
  consecutive genuine failures.
- **`runAction` must carry segments** (I2).
- Wall clock for a 124k-token note is roughly **9–16 min**, ~11–14 passes. That
  is the honest price of local privacy on a 2-hour call; show it, don't hide it.

## Constraints and traps

- **Plan first, then a `fable` adversarial review, then code.** Mandatory per
  `CLAUDE.md`. The last review caught three CRITICAL defects that would have
  shipped broken — including a context resolver that produced 4096 on the very
  path that hung.
- **Never stack PRs on this repo.** #35 was stacked, merged into its already-merged
  base, and never reached `main` — the same failure as #22 → #27. Also, CodeQL
  only runs on PRs based on `main` (`codeql.yml` restricts `pull_request` to
  `branches: [main]`), so a stacked PR silently skips security analysis.
- **Verify merges by content, not the MERGED label.** `git cat-file -e
  origin/main:<path>` and grep `main`'s blob. `git branch -r --contains <sha>`
  gives a false negative after a squash or cherry-pick.
- **`better-sqlite3` ABI toggle.** `npm rebuild better-sqlite3` before tests;
  `npm run rebuild:native` before building. Mutually exclusive.
- **dmg build trap.** A failed dmg leaves `/Volumes/OpenWhispr*` mounted and the
  next build dies with `hdiutil: couldn't unmount ... Resource busy`. Detach the
  stale mounts, then `npx electron-builder --mac dmg --arm64` — do not re-run the
  whole build. Note `prebuild:mac` does **not** run for `build:mac:arm64` (npm
  only pairs `pre<exact-script-name>`).
- **Stage by explicit path.** Four untracked `docs/plans/2026-0[789]-*.md` and
  `2026-08-04-*.md` files must stay untracked. Never `git add -A`.
- `gh` defaults to the upstream repo — always `--repo futuregerald/openwhispr`.
- npm floor `>=11.11.0`; local npm 11.19.0. Never `npm@latest` on Node 25.
- "Build and Notarize" and "Release" workflows are `disabled_manually` **on
  purpose**. Do not re-enable.
- Never commit to `main`; never auto-merge.
